# Optional KyuGraph adapter

This native/server-side Rust component consumes the version-1 knowledge batches
generated by hxn-assets. It is separate from the portable Haxe package.

```rust
use hxn_assets_kyugraph::KnowledgeAdapter;
use kyu_graph::Database;

let database = Database::in_memory();
let mut adapter = KnowledgeAdapter::new(database.connect())?;
adapter.apply_json(&batch_json)?;
```

The application owns authorization, scheduling and transport. Serialize writes
per database and keep them off a render/event thread. Schemas require explicit
migration. Scalar arrays use JSON text STRING columns for KyuGraph 0.4 DDL.
Queries must scope namespaces and exclude tombstones; namespace separation does
not replace endpoint authorization.

examples/replay.rs executes the lore/progress/NPC/spatial query from the Haxe
demonstration. From the workspace root, `python3 tests/knowledge/run.py --adapter`
exports the real Haxe batches and verifies replay and database restart. Use
`--kyugraph <checkout>` to exercise local engine source. This optional crate has
not been published and is not bundled into the haxelib.

Retain [third-party notices](third-party/NOTICES.md) and applicable source archives
with redistributed binaries. The locked inventory belongs to this component;
portable hxn-file has its own inventory. See the
[knowledge contract](../../docs/knowledge.md) for wire and lifecycle semantics.
